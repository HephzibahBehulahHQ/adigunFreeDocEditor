# Feature matrix

Status is specific to the current first workspace slice.

| Feature | Current status | Evidence / limit |
|---|---|---|
| Responsive workspace shell and entry screen | Implemented | `index.html` and responsive rules in `styles.css`. |
| Settings and local data controls | Partial | Autosave, theme, page defaults, browser spellcheck language hint, and confirmed deletion of local documents are available. The application interface remains English-only; AI consent is not exposed because no provider is configured. |
| Page setup controls | Partial | A4/US Letter, portrait/landscape and Normal/Narrow/Wide presets persist per document and map to DOCX. Custom per-side margins can be entered in millimeters, saved, imported from consistent supported sections, displayed in the editor, and exported to DOCX; values are limited to 100 mm per side and leave printable content area. The editing surface groups content into paper-sized sheets, splits long paragraphs and headings without images at word boundaries (using Unicode code point boundaries for an unbroken word), splits text-only list items across sheets and continues ordered numbering, and splits tables with standard `thead`/`tbody` structure between rows while repeating their header, including oversized rows with horizontally merged cells and text-only content; vertical-merge groups stay together and can exceed a sheet if the full group does not fit; images in table cells scale to the remaining table-body height, while direct nested lists with text-only items split between items; complex nested list items and nested tables with vertical merges can still exceed a sheet, while images scale to the available page content height and width. Page thumbnails navigate the sheets; this approximate layout does not reproduce Word pagination. Optional centered text headers and footers repeat on editor sheets and export as DOCX header/footer parts. Optional page numbers show on sheets and export as dynamic PAGE fields.
| Local conversion workspace | Partial | Converts DOCX, TXT, Markdown and HTML locally to HTML or DOCX, with a sandboxed preview, progress state, compatibility warnings and download. Markdown and HTML source formatting is flattened; PDF conversion is unsupported. |
| Landing file drop | Implemented | Keyboard-accessible file picker and file drag-and-drop support DOCX, PDF, TXT, Markdown and HTML; unsupported extensions are rejected. |
| Starter templates | Implemented | Six editable on-device templates cover meeting notes, project briefs, formal letters, status reports, research notes, and resumes; selecting a card opens a populated document without sending content to a service. |
| Document outline navigation | Implemented | Heading levels 1–3 are listed from the open editable document; heading filter and click-to-navigate use current document content. On tablet and mobile the outline is collapsed by default into a single-column workspace and can be opened when needed. |
| Create blank document and basic editing | Implemented | Browser editing surface and Home/Insert/Layout/Review/View controls; text style, supported font family and size, text and highlight colors, paragraph and line spacing, indentation, emphasis, list and alignment controls reflect the current caret or selection. Ctrl/Command+Enter inserts a page break when the editor selection is active; the Insert ribbon exposes the shortcut in its tooltip and `aria-keyshortcuts`. |
| Open document tabs | Partial | Open editable documents can be switched and closed, then restored for the current browser tab session from IDs in session storage and saved document records in IndexedDB; document text and titles are not stored in the tab session. Missing or deleted records are skipped. PDF preview tabs retain the selected File object in memory and close with the session. |
| Structured document model | Partial | Versioned allow-listed node tree is the source for local persistence and exports. The live Tiptap schema covers supported blocks, marks, tables, images, revisions, and custom attributes; visual sheet wrappers are flattened when mapped into the stored model. The toolbar routes supported formatting commands through Tiptap transactions, with browser-command fallback for controls not yet mapped. Visual paragraph, heading, list-item, and table-row fragments are rejoined in the model for saving and export; complex list items and table rows with vertical merges remain intact and may grow beyond a sheet. |
| Insert and edit tables | Partial | Insert up to 50 rows × 20 columns, add rows or columns beside the current cell, delete rows, columns or a table, merge adjacent cells horizontally or vertically, and split merged cells into smaller spans. The last row and column are retained. |
| Insert and position local images | Partial | PNG, JPEG and GIF up to 8 MB are stored in the browser document. Selected images can have editable alternative text and pixel width, plus left, center, or right paragraph alignment; they scale down to fit the page content width and height while preserving aspect ratio. Cropping, rotation, and text wrapping are not supported. |
| Autosave and reopen | Implemented | IndexedDB; preference is stored locally; toolbar Save and Ctrl+S are available. |
| TXT, Markdown and HTML import | Implemented | Imports plain text into the editor; source HTML formatting is not preserved. |
| PDF viewing and download | Implemented | Browser PDF viewer; editing and page operations are not supported. |
| HTML export | Implemented | Downloads the current editable document as an HTML file. |
| Local document overview | Implemented | Extracts sentences from the current document; not an AI summary. The Adigun local-tools panel docks in a dedicated, keyboard- and pointer-resizable right rail on wide screens and remains floating at narrower widths. |
| DOCX export | Partial | Creates a real OOXML `.docx` package; maps headings, supported font families, colors/highlights, paragraph/line spacing and indentation, emphasis, web links, lists, tables, header rows, horizontal and vertical cell spans, PNG/JPEG/GIF images, page setup, and tracked insertions/deletions as `w:ins`/`w:del` with author/date. WebP/SVG images and advanced styles are not preserved. |
| DOCX import | Partial | Mammoth converts semantic structure in-browser; allow-listed HTML is sanitized. Headings, lists, tables, safe inline raster images, supported A4/US Letter size/orientation, preset margins, and custom per-side margins up to 100 mm can be edited. All sections must agree; gutters, custom page sizes, mixed sections, first/even-page header/footer variants, unsupported fields, advanced styling, and full fidelity are not preserved. Supported default header/footer text and PAGE fields import; unsupported settings generate a warning. Simple paragraph revisions are mapped when converted text aligns exactly; unaligned or unsupported revisions may be lost. |
| PDF annotation, modification or conversion | Not implemented | No PDF editing/conversion engine is included. |
| Hosted AI, translation or rewriting | Not implemented | No provider or backend is configured; no simulated results. |
| Accounts, cloud sync or shared documents | Not implemented | No identity or remote persistence service exists in this repository. |
| Find and replace | Implemented | Searches editable document text, navigates matches, and replaces one or all matches. Replace all is disabled above 5,000 matches to keep large edits bounded. |
| Strikethrough formatting | Implemented | Applies to selected text and persists through the local document model, DOCX import and DOCX export. |
| Document comments | Partial | Quote- and context-anchored comments are saved with the local document; comments can be resolved and reopened. DOCX import brings in comments whose selected text can be matched, preserving author, date, and resolved status; comments with missing, unsupported, or unmatched text anchors are reported. Anchored comments export as native Word comments; conversion warns that source comments are not retained. |
| Track changes and review history | Partial | Opt-in local tracking captures plain text insertions and same-paragraph deletions, with author/time metadata and per-change or bulk accept/reject actions. Revisions persist when reopened and export as OOXML `w:ins`/`w:del` with author/date. Formatting and multi-paragraph edits are not tracked; simple imported DOCX revisions are reviewable when paragraph alignment is exact. |
